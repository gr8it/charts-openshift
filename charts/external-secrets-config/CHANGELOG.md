## [2.0.0] - 2026-11-19

### Changed

- **Breaking:** requires Kyverno >= 1.19, `ClusterPolicy`/`ClusterCleanupPolicy` migrated to CEL
- `app-project-eso-vault` → `GeneratingPolicy` for the synchronized SecretStore and auth-delegator ClusterRoleBinding (name kept, existing resources are adopted)
- `vault-auth` ServiceAccount and AuthBackendRole moved to `app-project-eso-vault-sa` and `app-project-eso-vault-auth-backend-role`, created only when missing
- `policy-svc-vie` → `GeneratingPolicy` (server-side apply), generated once the Backend reports its accessor
- `app-project-eso-vault-cleanup` → `DeletingPolicy`, also cleans up AuthBackendRoles generated by the legacy ClusterPolicy
- background controller can get/list/watch SecretStores, ClusterRoleBindings and vault Policies (Kyverno >= 1.19 watches synchronized downstream resources)
- `app-project-eso-vault` and `policy-svc-vie` keep the generated resources when the policy is deleted (`orphanDownstreamOnPolicyDelete`), same as the pre-2.0.0 `ClusterPolicy`, so rolling back to the `ClusterPolicy` does not delete them

_([SPEXAPC-32527](https://aspecta.atlassian.net/browse/SPEXAPC-32527))_
