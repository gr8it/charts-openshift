# Changelog

All notable changes to this component will be documented in this file.

The format is based on [Common Changelog](https://common-changelog.org/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0] - 2026-11-19

### Changed

- **Breaking:** requires Kyverno >= 1.19; legacy `ClusterPolicy`/`ClusterCleanupPolicy` migrated to CEL policies (`policies.kyverno.io/v1`)
- `app-project-internetproxy-cm` → `GeneratingPolicy` (name kept, existing ConfigMaps are adopted)
- `app-project-limitrange` and `app-project-quotas` → one `GeneratingPolicy` per LimitRange/ResourceQuota (`app-project-limitrange`, `app-project-default-resource-quota`, `app-project-cnpg-custom-resource-quota`, `app-project-monitoring-quota`, `app-project-grafana-quota`, `app-project-kubevirt-cr-quota`), created only when missing so manual changes are kept
- `app-project-namespace-metadata` → three `MutatingPolicy`: `app-project-namespace-metadata` (Namespace labels from the ConfigMap), `app-project-service-metadata` (Service labels on admission), `app-project-service-metadata-existing` (labels of existing Services)
- `app-project-require-metadata-configmap` → audit-only `ValidatingPolicy`
- `app-project-vault-groups` → `GeneratingPolicy` per vault role and kind (`app-project-vault-groups-<role>-policy`, `app-project-vault-groups-<role>-group`), created only when missing
- `app-project-vault-groups-cleanup` → `DeletingPolicy`, also cleans up resources generated by the legacy ClusterPolicy

_([SPEXAPC-32527](https://aspecta.atlassian.net/browse/SPEXAPC-32527))_

## [1.5.1] - 2026-10-01

### Added

- `app-project-namespace-metadata` mirrors the `team` and `vendor` namespace labels onto Services in application namespaces

### Changed

- `app-project-require-metadata-configmap` is evaluated only by background scans, no longer on namespace admission

## [1.5.0] - 2026-09-23

### Added

- `app-project-namespace-metadata` copies every key of the `project-metadata` configmap onto the Namespace as a label, so that metrics can be attributed to the project instead of the `prometheusK8s.externalLabels` platform default. Entries whose value is not a valid Kubernetes label value are skipped instead of failing the patch
- `app-project-require-metadata-configmap` reports, in Audit mode, an application namespace in which no `project-metadata` ConfigMap exists
- aggregated ClusterRole letting the background controller patch Namespace labels
